What is Agent Harness for WordPress?

Agent Harness for WordPress is a local, disposable WordPress install for AI coding agents. It runs WordPress and MariaDB in Docker on loopback, exposes site abilities through the official WordPress MCP Adapter, and resets with one command. The repo wires the stack; it does not ship an MCP server or plugin of its own.

What you get

A disposable harness, not a hosted WordPress. The MCP server and abilities come from upstream; this repo makes them reproducible.

Docker

WordPress and MariaDB published on 127.0.0.1 only, so nothing else on your network can reach them.

MCP Adapter

Three meta-tools: discover abilities, inspect a schema, execute. The agent reads real ability names instead of guessing them.

29 abilities

26 MS WordPress Abilities and 3 core ones: posts, pages, media, menus, plugins, themes, settings, and a bridge to any REST route.

Five test layers

From repo checks to a real headless Claude Code session, whose every step is checked against the database with WP-CLI.

Agent skills

Curated WordPress skills for blocks, block themes, plugins, REST, the Abilities API, and WP-CLI, ready in Claude Code and Cursor.

One-command reset

./bin/reset rebuilds a clean site in one go. Running ./bin/setup again is safe and never wipes content.

How a request travels

Every prompt takes the same path, so when something fails you know which layer to look at.

  1. Agent

    Claude Code, Cursor, or Codex sends an HTTP MCP request, authenticated with a revocable Application Password.

  2. MCP Adapter

    Listens on 127.0.0.1:8080 and answers with three meta-tools instead of thirty tools.

  3. Abilities API

    Runs the ability with WordPress capability checks, the same rules wp-admin follows.

  4. WordPress

    A real install on Twenty Twenty-Five and MariaDB, with all data in disposable Docker volumes.

./bin/wp ability list skips MCP entirely: if an ability works there but not in your agent, the problem is in the MCP layer, not in WordPress.

Quick start

Needs Docker Compose v2, Git, and Bash. About ten minutes from clone to first prompt.

Questions answered

Which AI coding agents work with it?

Claude Code, Cursor, and Codex connect over HTTP MCP to the same endpoint. ./bin/connect registers it with Claude Code; ./bin/connect --print prints the URL and Authorization header for Cursor, and the variable the repo's .codex/config.toml reads for Codex.

Is the WordPress site public?

No. WordPress is published on 127.0.0.1:8080 and MariaDB on 127.0.0.1:3307, so no other machine can reach them. This website only describes the harness and has no MCP endpoint.

Will the agent publish or delete things on its own?

The harness rules tell agents to work in drafts and to state a change before applying it, but that is a working convention, not a control. An MCP connection is admin access; MS WordPress Abilities hard-blocks only a few routes, such as permanent deletes and writes to users and settings. That is why the endpoint never leaves your machine.

How do you reset the local site?

Run ./bin/reset. It removes the containers and both Docker volumes, then runs ./bin/setup again for a clean install; --no-setup stops after the wipe. ./bin/setup on its own is idempotent and never wipes content.

Can I point an agent at a live site?

The same MCP path works against any WordPress 6.9+ site running the MCP Adapter and MS WordPress Abilities, with an Application Password. Connecting to a live site covers it, and it leaves the harness behind: no reset, no pinned stack, every call a real change.

Does this repo ship an MCP server or plugin?

No. The MCP Adapter and MS WordPress Abilities come from upstream, pinned to tested releases. This repository provides Docker Compose, provisioning, tests, docs, and curated WordPress agent skills.
